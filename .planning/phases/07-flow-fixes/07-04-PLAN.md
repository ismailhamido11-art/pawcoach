<objective>
Corriger 5 suspects critiques P1 concentrés sur Home, Dashboard, Nutri et DogProfile.

FIX-21 : Dashboard.Promise.all — 5 des 7 appels n'ont pas de `.catch(() => [])` individuel. Une seule erreur réseau sur HealthRecord (la plus fréquente) vide entièrement le Dashboard. FoodScans et GrowthEntries sont déjà protégés — ajouter la même protection aux 5 autres.

FIX-22 : Home background refresh silencieux — quand `fetchAndCache(true)` échoue, l'erreur est avalée (if !skipLoadingState protège le toast mais laisse les données périmées sans signal). Ajouter un indicateur visuel discret (badge ou state `isDataStale`).

FIX-23 : Quick check-in — `result.checkin` peut être absent de la réponse API. Le fallback construit un objet sans `id`. Toute opération future sur `todayCheckin.id` plante silencieusement. Fix : si `result.checkin` absent, re-fetcher depuis l'API ou rejeter proprement.

FIX-24 : NutriCoach — quand quota_exceeded (429), `setMessagesRemaining(0)` est appelé mais aucun toast n'informe l'utilisateur. L'utilisateur voit son crédit passer à 0 sans explication.

FIX-27 : DogProfile export — `URL.revokeObjectURL(url)` est appelé immédiatement après `a.click()`. Sur mobile, le download n'a pas eu le temps de démarrer → fichier parfois vide. Fix : différer à 5 secondes.

Purpose: Zéro écran blanc sur Dashboard, zéro donnée périmée silencieuse, zéro checkin orphelin, toast 429 visible, export mobile fiable.
Output: 4 fichiers corrigés.

Ajouter ce useEffect APRES le bloc `useEffect(() => { if (!isLoadingAuth) ... }, [isLoadingAuth, authUser]);` (vers ligne 241).

   Le code a ajouter :
   ```javascript
   // CACHE-04: Refresh recentScans when user returns to this page (e.g. after Scan)
   useEffect(() => {
     const handleVisibility = () => {
       if (document.visibilityState === "visible" && dog) {
         FoodScan.filter({ dog_id: dog.id }, "-timestamp", 5)
           .then(scans => setRecentScans(scans || []))
           .catch(() => {});
       }
     };
     document.addEventListener("visibilitychange", handleVisibility);
     return () => document.removeEventListener("visibilitychange", handleVisibility);
   }, [dog?.id]);
   ```

   IMPORTANT: La dependance est `dog?.id` (pas `dog`) pour eviter des re-registrations inutiles du listener.

   IMPORTANT: `FoodScan` est deja importe dans Nutri.jsx (ligne ~30-40 dans les imports d'entites). Verifier avec grep avant d'ajouter un import en double.

   NOTE: `visibilitychange` est le pattern standard pour les SPA avec navigation React Router. Quand l'utilisateur va sur /Scan puis revient sur /Nutri via le bouton "Retour a Nutri" ou la BottomNav, React Router ne remonte pas le composant si Nutri est eager-loaded. Le `visibilitychange` se declenche sur les tab switches mobiles. Pour couvrir aussi la navigation intra-SPA, on utilise en plus un refetch sur le changement de `activeTab` qui revient sur un onglet montrant les scans.

   En fait, dans une SPA React Router, quand on navigue de /Nutri vers /Scan puis retour, le composant Nutri est RE-MONTE (les pages non-lazy sont dans des Routes, donc unmount/remount). L'init() dans useEffect s'execute deja au remount. Donc le vrai probleme est : est-ce que Nutri garde son state entre navigations ?

   Verifier : Nutri.jsx est eager-loaded (importe directement dans pages.config.js), mais le Route unmount/remount le composant a chaque navigation. Donc `init()` se relance et recharge les scans.

   CORRECTION: Apres reflexion, si le composant est remonte, `init()` est rappele et les scans sont recharges. Le probleme n'est PAS le remount mais le cas ou le composant reste monte (improbable avec React Router v6 Routes). Pour etre robuste, ajoutons quand meme le `visibilitychange` listener pour le cas mobile (onglet en arriere-plan).

   Le vrai fix robuste : ajouter aussi un refetch basique au focus de la fenetre.

   Ajouter plutot ce pattern :
   ```javascript
   // CACHE-04: Refresh recentScans when returning to this page
   useEffect(() => {
     const refreshScans = () => {
       if (dog?.id) {
         FoodScan.filter({ dog_id: dog.id }, "-timestamp", 5)
           .then(scans => setRecentScans(scans || []))
           .catch(() => {});
       }
     };
     window.addEventListener("focus", refreshScans);
     document.addEventListener("visibilitychange", () => {
       if (document.visibilityState === "visible") refreshScans();
     });
     return () => {
       window.removeEventListener("focus", refreshScans);
       document.removeEventListener("visibilitychange", refreshScans);
     };
   }, [dog?.id]);
   ```

   WAIT — le removeEventListener doit retirer la meme reference. Corrigeons :

## Directory Purposes

**`src/pages/` — 16 Page Components:**
- Purpose: Top-level route components; each owns its full data lifecycle
- Eager (BottomNav tabs — in initial bundle): `Home.jsx`, `Sante.jsx`, `Activite.jsx`, `Nutri.jsx`, `Profile.jsx`
- Lazy (loaded on demand): `Chat.jsx`, `Dashboard.jsx`, `DogProfile.jsx`, `DogPublicProfile.jsx`, `Library.jsx`, `Onboarding.jsx`, `Premium.jsx`, `Scan.jsx`, `Training.jsx`, `VetDogView.jsx`, `VetPortal.jsx`
- Public routes (no auth): `DogPublicProfile.jsx`, `VetDogView.jsx`

**`src/components/ui/` — Primitives (IMMUTABLE):**
- shadcn/ui components (Radix-based): `button`, `dialog`, `card`, `input`, `badge`, `drawer`, etc.
- Custom primitives: `SkeletonPage.jsx`, `EmptyState.jsx`, `IconBadge.jsx`, `StorysetIllustration.jsx`, `LottieAnimation.jsx`, `PawIllustrations.jsx`, `AICreditsGate.jsx`, `MobileSelect.jsx`, `VoiceInput.jsx`
- Rule: Never modify anything in this directory

**`src/components/{domain}/` — Feature Components:**
- Colocated by page/feature domain
- Can make API calls for mutations; receive data as props for display

**`src/api/` — Data Access:**
- Single file for entities (`entities.js`) exports all 19 named entity objects
- Entities: `Dog`, `HealthRecord`, `DailyCheckin`, `DailyLog`, `Streak`, `FoodScan`, `UserProgress`, `DiagnosisReport`, `NutritionPlan`, `Bookmark`, `WeeklyInsight`, `SharedVetAccess`, `DogAchievement`, `DietPreferences`, `GrowthEntry`, `ParkReview`, `PlaceFavorite`, `ChatMessage`, `VetNote`

**`src/lib/` — App Infrastructure:**
- Contexts, animation presets, SDK config — app-wide concerns
- Not to be confused with `src/components/lib/` (which contains only `markdown.jsx`)

**`src/utils/` — Business Logic:**
- Pure functions, no React imports (except `chartHelpers.jsx` which uses JSX for Recharts tooltip)
- Import from: `@/utils/premium`, `@/utils/recommendations`, `@/utils/healthStatus`, `@/utils/dateHelpers`, `@/utils/ai-credits`, `@/utils/analytics`

**`base44/functions/` — Backend:**
- Each function is a separate directory with its own Deno entry point
- Called via `base44.functions.invoke(name, payload)` or scheduled by Base44

## Key File Locations

**Entry Points:**
- `src/main.jsx`: React app mount point
- `src/App.jsx`: Router, providers, auth guard
- `src/pages.config.js`: Route registry and main page declaration

**Configuration:**
- `src/lib/app-params.js`: Base44 app ID, auth token, functions version (reads from URL params then localStorage)
- `vite.config.js`: Build config, path aliases
- `jsconfig.json`: TypeScript/IDE path aliases (`@/` → `src/`)
- `tailwind.config.js`: Design system extension
- `src/index.css`: CSS custom properties (colors, spacing) — DO NOT MODIFY color vars

**Core Logic:**
- `src/api/entities.js`: All entity access (import named entities from here)
- `src/lib/AuthContext.jsx`: Auth state + user object source of truth
- `src/lib/HomeCacheContext.jsx`: Home cache invalidation entry point
- `src/utils/index.ts`: `getActiveDog()` and `createPageUrl()` — used everywhere
- `src/utils/premium.js`: Premium gate logic — used in every page and many components
- `src/components/streakHelper.jsx`: Streak update logic called after health activities

**Global Components:**
- `src/components/BottomNav.jsx`: Main 5-tab navigation
- `src/components/CombinedFAB.jsx`: Quick-log floating action button (Home only)
- `src/components/ChatFAB.jsx`: Chat floating action button (secondary pages)
- `src/components/PullToRefresh.jsx`: Pull-to-refresh wrapper
- `src/components/ErrorBoundary.jsx`: React error boundary
- `src/components/PawLoader.jsx`: Full-screen loading spinner
- `src/components/WellnessBanner.jsx`: Wellness score banner (used in Sante, Activite, Nutri)

## Naming Conventions

**Files:**
- Page components: `PascalCase.jsx` matching the route key exactly (e.g., `Home.jsx` → route `/Home`)
- Feature components: `PascalCase.jsx` describing the component's role (e.g., `CoachHomeHeader.jsx`, `NotebookContent.jsx`)
- Utilities: `camelCase.js` or `camelCase.ts` (e.g., `healthStatus.js`, `dateHelpers.js`)
- Hooks: `useCamelCase.js` or `useCamelCase.jsx`
- Contexts: `PascalCaseContext.jsx`

**Directories:**
- Feature component directories: `lowercase` matching their domain (e.g., `home/`, `sante/`, `nutrition/`)
- Backend functions: `camelCase/` (e.g., `pawcoachChat/`, `stripeWebhook/`)

**Variables and Functions:**
- React components: `PascalCase`
- Utility functions: `camelCase` (e.g., `isUserPremium`, `getActiveDog`, `buildRecommendations`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `MSG_DAILY_LIMIT`, `CACHE_TTL`, `MILESTONES`, `TABS`, `FIELDS`)
- Entity names: `PascalCase` matching Base44 schema (e.g., `Dog`, `HealthRecord`, `DailyCheckin`)

## Where to Add New Code

**New Page:**
1. Create `src/pages/NewPage.jsx` — Base44 auto-registers it
2. Add to `PAGES` in `src/pages.config.js` (eager or lazy)
3. Add to `SECONDARY_PAGE_PARENT` in `src/components/BottomNav.jsx` if it belongs to a parent tab
4. Create components in `src/components/newpage/` for feature-specific UI

**New Feature Component (within an existing page):**
1. Add to `src/components/{domain}/NewComponent.jsx`
2. Import into the page or parent component
3. If it needs entity data for mutations: import directly from `@/api/entities`
4. If it needs auth state: import `useAuth` from `@/lib/AuthContext`

**New Utility Function:**
1. Pure business logic: add to the appropriate file in `src/utils/` or create `src/utils/newDomain.js`
2. App infrastructure (contexts, SDK wrappers): add to `src/lib/`
3. Reusable React hook: add to `src/hooks/useNewHook.js`

**New Backend Function:**
1. Create directory `base44/functions/newFunctionName/`
2. Add Deno entry point inside the directory
3. Call from frontend: `base44.functions.invoke("newFunctionName", payload)`

**New Entity:**
1. Add schema via Base44 Build prompt (only way to modify schema)
2. Add wrapper to `src/api/entities.js`: `export const NewEntity = wrapEntity(base44.entities.NewEntity, "NewEntity");`
